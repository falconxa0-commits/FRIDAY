## Phase 5 — AI Intelligence Audit

### Execution Flow: User Message → Response

```
User sends message
    ↓
FridayBrain.chat_stream(message)
    ↓
1. Emotion detection (core/emotions.py:157)
   → detect_emotion(message) → current_emotion updated
    ↓
2. Memory store (core/memory.py:119)
   → store_conversation("user", message)
    ↓
3. Creative route detection (core/brain.py:573)
   → _detect_creative_route(message)
   → If image/video pattern: route to ImageGen/VideoGen, RETURN
    ↓
4. Provider routing (core/brain.py:687-730)
   ├── GLM (default, free):
   │   a. Build system prompt (identity + mood + personality + summaries)
   │   b. Inject RAG context (retrieve memories + subconscious intuition)
   │   c. Call glm_brain.chat_stream() — stream tokens
   │   d. Store assistant response in memory
   │   e. RETURN (NO tool calling)
   │
   ├── Ollama (local):
   │   → local_brain.chat_stream(message) → RETURN
   │
   ├── Gemini:
   │   → gemini_brain.chat_stream(message) → RETURN
   │
   └── Claude (paid, has tool calling):
       a. Build system prompt
       b. Inject RAG context
       c. Add to conversation_history
       d. Summarize older messages
       e. TOOL CALLING LOOP (max 5 rounds):
          i.   Stream response via client.messages.stream()
          ii.  Collect text chunks → yield to caller
          iii. Check for tool_use blocks
          iv.  If tools called: execute each tool → add results → continue loop
          v.   If no tools: store response, BREAK
       f. Store assistant response in memory
```

### Key AI Architecture Findings

**Finding 1: GLM branch has NO tool calling.**
The GLM branch (`core/brain.py:687-708`) streams a response and returns. It does NOT enter the tool-calling loop. Only the Claude branch (`core/brain.py:738-832`) has the 5-round tool-use loop with `access_universal_service`, `search_web`, `remember`, `recall_memories`, `run_skill`. This means free-tier users (the default) get chat + creative routing but NOT tool-augmented reasoning.

**Finding 2: Subconscious mind is wired into RAG.**
`_inject_rag_context()` (`core/brain.py:545-559`) now calls `SubconsciousMind.get_intuition()` and appends it to the RAG context. This means every GLM response may include subconscious insights surfaced from vector memory patterns.

**Finding 3: Memory bug is fixed.**
The GLM branch (`core/brain.py:702`) now stores `full_response` as `"assistant"` role. Previously it stored the user message a second time as `"user"` role and never stored the assistant response.

**Finding 4: RAG pipeline is real.**
`RAGPipeline.retrieve_context()` (`core/brain.py:109`) calls `memory.retrieve_relevant_memories(query)` which tries vector store first, falls back to keyword search. The retrieved context is prepended to the user message.

**Finding 5: Council mode is real parallel dispatch.**
`run_council()` (`core/council_mode.py:229`) uses `asyncio.gather()` to dispatch to all configured providers in parallel. GLM is always included (free tier). Agreement analysis uses sentence-level Jaccard overlap.

### Overall Engineering Assessment

FRIDAY v3.0 is a **genuinely innovative personal AI assistant** with several capabilities no other open-source project offers. The architecture is well-organized with clean plugin auto-discovery, a tamper-evident hash-chained ledger, MCP protocol support with `request_approval` for external agent gating, and a subconscious mind module integrated into the RAG pipeline. The v3.0 release successfully wired 8 previously-orphaned modules, fixed the broken rate limiting (now actually enforces 429s), added MCP audit logging for all tools, and introduced goals, webhooks, notifications, SDK, and deployment configs.

However, the project is **not yet production-ready**. The Dockerfile runs as root, 4 modules remain orphaned (including security-sensitive ones like `privacy_audit.py`), the god class `FridayBrain` is 868 lines, 321 `except Exception` blocks mask errors, and the GLM branch (the default free-tier provider) lacks tool calling — meaning free-tier users get chat but not tool-augmented reasoning. There is no CI/CD pipeline, and the README hasn't been updated for v3.0 features.

The project needs **one focused day of work** (P0 items: Dockerfile USER, delete orphans, add CI/CD, add token to install.ps1, remove unused slowapi, update README, add tool calling to GLM branch) to be genuinely open-source-ready. After that, it would be a compelling, differentiated AI assistant with genuine Z.ai free-tier integration, a security infrastructure that most open-source AI assistants lack entirely, and an architecture that supports rapid extension via plugins, skills, MCP tools, and identity modes.
